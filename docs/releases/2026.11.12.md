# v2026.11.12 — sub2api 接入与多 Key 支持

日期版本：2026-11-12（Asia/Shanghai）。本次发布范围为 Web 与 Docker，不包含桌面安装包。

## 新增

- 支持从受信 sub2api 站点通过 `user_id` 与登录 access token 进入 Chat，校验身份后关联独立普通用户。
- 支持 query 与 fragment 入口；读取后清理地址栏中的凭据，失败时隔离旧会话，保留本地 2FA。
- 同步 sub2api 昵称、用户名与展示邮箱；来源邮箱不参与 Chat 密码找回、邮箱验证或账户自动合并。
- 对全部有效且兼容的 Key 分别尝试幂等导入，服务名称包含 Key 名称、分组及编号；同名模型保持独立引用，由用户手动选择。
- 提供导入、复用、跳过、失败的摘要与逐项原因；保留手动名称、模型选择及管理员停用状态。
- 增加默认关闭的受限 iframe 支持：显式开启后只允许配置的 sub2api 管理站点 origin 嵌入。
- 兼容 sub2api 认证错误的 `reason` 和字符串 `code` 响应，使用白名单诊断信息，不回显凭据或上游错误原文。

## 安全与兼容

- 固定可信 HTTPS 管理地址、严格公网出站校验、禁止重定向、强制兑换限流，以及响应大小、分页和时间预算限制。
- 新身份按“实例 + 远端用户 ID”绑定，不按邮箱或昵称认领已有本地账号。
- API Key 继续使用原有绑定加密存储；不会在 sub2api 自动创建 Key 或扩大配额。
- 旧单 Key 记录沿用原 provider ID；新增展示字段与自动名称记录通过正常数据库迁移添加。
- Git 与 Docker 构建上下文排除本地配置、环境凭据、数据库、日志、缓存和内部代理报告。

## 启用接入

在实际部署配置中添加可信实例：

```yaml
sub2api:
  enabled: true
  base_url: "https://sub2api.example.com"
  api_base_url: ""
  allow_embedding: false
```

同时在 Chat 管理后台开启“个人模型服务”。如果网关与管理站点不同 origin，应显式配置 `api_base_url`。

使用现有 Compose 时，通过环境变量选择本次镜像，不要继续使用未包含本分支改动的上游镜像：

```bash
# 在 deploy 目录中，先准备好实际 config.yaml。
DEEIX_CHAT_IMAGE=195658/deeix-chat:2026.11.12 docker compose -f docker-compose.sqlite.yml up -d
```

完整说明：[sub2api 接入与限制](<../../deploy/SUB2API.md>)。

## 升级前请注意

1. 先备份数据库、存储目录和数据加密密钥；不要为了升级删除数据库。
2. 从 sub2api 菜单重新进入才能触发资料和 Key 同步，刷新 Chat 的既有 Cookie 会话不会重新读取远端资料。
3. 目前自动导入支持 OpenAI、Anthropic、Gemini 分组；个人服务数量上限仍有效，默认 10，超出会明确报告。
4. sub2api 开启 IP/UA 会话绑定时，浏览器 token 经 Chat 后端验证可能被拒绝；本实现不会绕过绑定。长期集成建议专用授权交接。
5. Chat 本地启用 2FA 的账号只复用已有服务，不自动补导入新 Key 或更新来源资料；没有第二因素完成后的延迟同步。
6. 远端撤销/缺席的历史本地服务不会自动删除或停用；实际模型调用继续由远端鉴权。
7. 受限 iframe 允许列表不能绕过浏览器第三方 Cookie、本地网络权限或父站点 CSP 限制。
