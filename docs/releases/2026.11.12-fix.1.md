# v2026.11.12-fix.1 — DeepSeek 与可控协议选择

这是 `v2026.11.12` 的独立修复版本，不覆盖原标签。本版本仍只发布 Web／Docker，不包含桌面安装包。

## 修复与新增

- 修复 DeepSeek 分组被导入白名单误排除：`deepseek` 默认按 sub2api 的 OpenAI Responses 网关接入，而非直接认定不支持。
- 对平台协议无法确定、其他条件合格的 Key，先询问用户使用 **OpenAI Responses**、**Anthropic Messages** 或 **OpenAI Chat Completions**，也可选择本次跳过。
- 按 Key 独立选择；导入成功后记住所选协议，不自动跨 Key 轮换或故障切换。
- 协议确认阶段不创建本地账号或模型服务、不签发 Chat 会话；确认请求仍重新核验 token、用户身份、Key 归属及安全策略。
- 提示文案不再把“未知平台”与“无效 Key”混为一谈。

## 使用方式

沿用原 Compose 文件、数据库及配置，仅将镜像改为：

```text
195658/deeix-chat:2026.11.12-fix.1
```

在原部署目录执行（使用自定义 Compose 文件时保留原来的 `-f` 参数）：

```bash
export DEEIX_CHAT_IMAGE=195658/deeix-chat:2026.11.12-fix.1
docker compose pull app
docker compose up -d app
```

本修订标签按镜像工作流规则**不会更新 `latest`**，也不会覆盖 `2026.11.12`；请明确使用修复版标签。升级前备份数据库和加密密钥，不要删库，不要重新生成已有数据的加密密钥。

升级后，从 sub2api 的菜单重新进入，触发新的接入请求。DeepSeek 默认使用 Responses；不确定的平台会显示协议选择界面。复制已经清理过的 Chat 地址栏 URL 不会重新携带登录凭据。

## 边界

- 协议选择不能绕过 Key 的归属、停用、过期、额度、主机策略和服务数量限制。
- 所有调用仍发往部署方信任的 sub2api 网关，不允许客户端提交任意上游地址或 API Key。
- 读取模型列表不代表相应生成接口必然可用；自动导入不执行收费推理探测。请按分组实际提供的协议选择。
- 已有服务的凭据、协议、手工模型配置及停用状态不会被新链接静默覆盖。
- 先前的 sub2api IP/UA 会话绑定、跨站 Cookie、Chat 本地 2FA 同步限制继续适用，详见 [接入说明](<../../deploy/SUB2API.md>)。

## 发布验证

以对应 GitHub CI、Image 工作流及 Docker Hub manifest 检查结果为准。源码测试使用合成凭据和假上游，不代表对用户真实 DeepSeek 生成接口完成了付费调用验证。
