# v2026.11.13-fix.1 — 用户来源资料与默认时区修复

## 修复内容

- 后台用户列表优先显示已同步的 **sub2api 用户名与邮箱**，不再用随机内部用户名作为主要识别信息。
- 来源用户名、邮箱和显示名参与服务器端搜索，在分页和总数计算前生效。
- 后台单行更新、编辑与头像展示保留来源资料；个人资料页也使用只读来源字段，头像和时区等本地设置仍可保存。
- 已绑定但未同步的记录显示远端用户 ID 和“待同步”，不编造姓名或邮箱。
- 新建用户默认时区改为 **Asia/Shanghai**，覆盖自动创建、注册、后台新增及数据库插入默认值。明确指定的其他时区和已有用户时区均保留。

这些改动不删除、合并或重新关联账号，不把来源邮箱设为本地已验证安全邮箱，也不改变已发布的 sub2api 密码验证方式。

## 升级

将原 Compose 使用的镜像设置为：

```text
195658/deeix-chat:2026.11.13-fix.1
```

然后在原部署目录执行（有 `-f` 参数时保留原参数）：

```bash
docker compose pull app
docker compose up -d app
```

保留数据卷、原配置和加密密钥。无需删库或重注册。已经同步过的来源资料可直接显示；没有保存来源资料的记录会如实标记待同步，原有 2FA 与资料同步边界保持。

本修订标签不覆盖 `2026.11.13` 或 Docker Hub `latest`，请使用明确版本标签。旧用户仍保留原时区，可在后台或个人设置中按需调整；本版本没有批量把所有旧 UTC 用户改为上海。

## 验证边界

验证使用合成用户与临时 SQLite／模拟浏览器，不读取或修改部署方真实账户。测试覆盖来源资料显示与搜索、分页、身份隔离、更新结果保留、新用户默认时区和旧时区保留。PostgreSQL 专项集成依赖外部测试 DSN，未提供时按现有测试条件跳过。
