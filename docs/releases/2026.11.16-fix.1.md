# v2026.11.16-fix.1 — 联网开关与实际请求对齐

## 修复

- **开关显示开启、请求却不带工具**：模型能力 JSON 里的 `nativeTools`/`nativeToolKeys`/`defaultOptions.tools` 为**空数组**时，过去会被当成“管理员接管”，导致 DeepSeek 厂商默认工具不再注入，而输入框的联网开关仍显示为开启。现在空数组视为“未声明”，按厂商默认开启；前后端判定规则完全一致。
- **只声明了其它厂商工具时静默失效**：DeepSeek 会忽略它不认识的服务端工具（官方文档：未识别的工具类型被忽略），而过去模型若声明了 OpenAI 的 `web_search` 等工具，就不会再追加 DeepSeek 自家工具，请求既不报错也不联网。现在路由厂商为 DeepSeek 且未声明任何 DeepSeek 工具时，改用 `deepseek_web_search` + `deepseek_read_url`（其它厂商工具会被丢弃，不再混发触发 400）。
- **显式关闭厂商默认注入**：模型能力 JSON 支持 `"disableVendorNativeTools": true` 或 `"vendorNativeTools": false`，用于管理员彻底关闭某模型的厂商默认联网工具，不再依赖“写空数组”这种歧义写法。
- **可观测性**：请求声明了 DeepSeek 联网工具、但上游既没有返回工具调用也没有引用时，后端记录 `vendor_native_tools_declared_but_unused` 告警（含 run id、协议、厂商、上游模型）。若升级后仍无法联网，这条日志可区分“平台没声明工具”和“中转网关静默丢弃了工具”。

## 使用与排查

- 升级后直接使用：DeepSeek 模型默认带联网工具，输入框联网开关可随时关闭/开启；关闭仍以 `options.tools: []` 下发，按模型记忆在本地。
- 仍无法联网时，按顺序检查：
  1. 运行中的镜像标签是否为 `2026.11.16-fix.1`；
  2. 后端日志是否出现 `vendor_native_tools_declared_but_unused`；
  3. 该模型的渠道协议与上游：DeepSeek 服务端工具需要上游确实支持（官方 API 的 Messages/Responses/Chat Completions 均支持）；经第三方中转或协议翻译时可能被丢弃；
  4. 模型能力 JSON 是否写了 `disableVendorNativeTools`。
