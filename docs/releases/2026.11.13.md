# v2026.11.13 — 使用 sub2api 邮箱密码登录

本版本新增 **Chat Web 直接使用 sub2api 邮箱和密码登录**。验证由配置的 sub2api 完成；Chat 不复制或保存远端密码。已有免登录用户仍关联同一个 Chat 账号，无需删库、重注册或修改内部用户名。

## 新增

- 登录页提供 sub2api 账号模式，保留明确的 Chat 本地账号／管理员入口，不按相同邮箱合并或自动尝试另一套密码。
- 动态读取源站能力：无验证码时直接验证；支持正常 Turnstile 和远端 TOTP。远端与 Chat 本地二次验证互不替代。
- 密码登录支持原有多 Key 导入、未知协议选择、跳过、重复 409 续接和结果摘要。
- 远端 token 保留在服务端短期内存，浏览器只持有 opaque flow ID。流程绑定 Cookie、IP/UA，具备固定五分钟 TTL、容量、并发和限流边界。
- 校验远端实例与网关快照，避免配置切换期间把旧凭证发到新目标；旧 flow 的取消不清除后来建立的会话 Cookie。

## 启用方式

新功能默认关闭。升级后，在实际挂载的配置文件中保留已有实例地址，只增加：

```yaml
sub2api:
  enabled: true
  password_login_enabled: true
  # 保留原有 base_url、api_base_url 和 allow_embedding
```

还需开启 Chat 的个人模型服务。环境变量 `SUB2API_PASSWORD_LOGIN_ENABLED` 优先于 YAML。更改配置后重启；如果改变了 Compose 环境或挂载，重新创建应用容器。

镜像：

```text
195658/deeix-chat:2026.11.13
```

稳定日期标签按既有工作流更新 Docker Hub `latest`，旧的 `2026.11.12` 和 `2026.11.12-fix.1` 固定标签保留。生产环境建议固定具体版本。

## 使用与边界

- 使用 sub2api 当前邮箱和密码；源站改密后，下次密码登录使用新密码。已经签发的 Chat 会话不会因此自动退出，可在 Chat 会话管理中处理。
- 当前实现为 Web-only，多副本需要粘性路由；重启或五分钟到期后需重新登录。
- Turnstile 是否出现取决于实际 `base_url` 对应的源站。开启时需授权 Chat hostname；不支持的验证码或额外同意流程会明确不可用，不绕过验证。
- 仍需至少一个可用个人模型服务；正确密码不代表所有 Key 或生成接口均可用。
- 远端 refresh token 只做单 token 尽力注销，不影响其他会话，不承诺上游一定成功删除。
- 不包含桌面安装包，不替部署方变更数据库、加密密钥或源站安全设置。
