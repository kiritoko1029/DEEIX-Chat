# v2026.11.16 — DeepSeek 联网工具与用户联网开关

## 新增

- 接入 DeepSeek 官方服务端联网工具 `deepseek_web_search` 与 `deepseek_read_url`，覆盖 Anthropic Messages、OpenAI Responses 与 OpenAI Chat Completions 三种协议。搜索、深度思考搜索（打开网页/页内查找）、图片搜索与阅读用户消息中的链接都会记录为可追溯的工具调用。
- **默认开启**：按路由厂商（`deepseek`）自动带上这两个工具，不要求管理员先给模型配置 `nativeTools`；管理员显式声明原生工具后由其完全接管，不再注入。
- **用户联网开关**：聊天输入框新增 Globe 按钮，用户可直接启停当前模型的联网能力，选择按模型保存在本地。关闭时客户端提交 `options.tools: []`，服务端据此不再补发默认工具；重置模型参数即恢复默认开启。
- **自动回退**：上游在请求被接受前明确拒绝这些声明时（400/404/415/422/500/502 且错误指向工具名或 unknown/unsupported/invalid 等），后端只剥离这两个 DeepSeek 工具、保留 MCP/函数工具与其他厂商原生工具，在同一路由重发一次，并在过程轨迹中留下“已自动回退为普通回答”的说明。内容审核、上下文超限、鉴权、余额与限流错误不会触发回退；已产生用量、推理或工具事件后不重发，避免重复计费。首轮生成、工具回灌与临时对话三处均覆盖。
- **结果展示**：搜索来源与阅读链接统一归一为来源卡片，带站点名、站点图标、摘要、发布时间、缩略图与失败原因；阅读链接使用独立分类与空态，工具行标题按“联网搜索/阅读链接”显示，中英文文案同步。

## 计费与安全边界

- DeepSeek 的 `usage.server_tool_use` 只取 `tool_search`、`tool_fetch`、`tool_image_search` 作为计费计数，展示用计数（`web_search_requests`、`web_fetch_requests`）不计费，避免误套 OpenAI/Anthropic 的按次价格。
- 搜索结果的 `encrypted_content` 与阅读链接的加密 `signature` 不落库、不下发；工具与引用中的链接只接受 HTTP(S)。
- 本轮未提供 DeepSeek 原生工具的默认按次价格，标记为 `notMetered`，管理员可按官方规则在计费设置中覆盖。

## 已知限制

- `deepseek_read_url` 抓取的网页正文以加密 `signature` 回传。本版本不保存该密文，因此**后续轮次无法把已阅读网页自动拼回上下文**（请求本身仍成功，只是网页正文不恢复）。若要多轮阅读，需要后续版本设计受控的原文存储与回放。
- 验证使用合成上游响应与单元测试，未对真实 DeepSeek 计费接口发起调用；转发端行为差异由自动回退兜底。
- 联网开关按浏览器本地缓存记忆，不同设备或清除缓存后会回到默认开启。

## 升级

将原 Compose 使用的镜像设置为：

```text
195658/deeix-chat:2026.11.16
```

然后在原部署目录执行（有 `-f` 参数时保留原参数）：

```bash
docker compose pull app
docker compose up -d app
```

保留数据卷、原配置与加密密钥，无需删库或重新导入。已存在的会话历史与模型配置不受影响；管理员此前显式配置过 `nativeTools`/`nativeToolKeys` 的模型继续按管理员配置执行，不会被本版本的厂商默认值覆盖。

本版本是稳定日期版本，按发布流程会同时更新 Docker Hub 的 `latest` 标签。需要固定内容时请使用 digest 或明确的版本标签。
